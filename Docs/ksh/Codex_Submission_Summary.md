# Codex와 함께 만든 SinkPoint Player·Gravity MVP

> 이 문서는 제출·영상 설명용 요약이다. 날짜별 구현 근거와 상세 검증 기록은 [Codex_Usage_Records.md](Codex_Usage_Records.md)에서 확인할 수 있다.

Codex는 SinkPoint의 Player·Gravity 파트에서 기존 Unity 프로젝트의 구조와 씬 상태를 분석하고, 구현 선택지를 비교하며, 최소 범위의 코드·Prefab·씬 연결과 문제 진단·검증을 지원하는 기술 협업 도구로 활용했다. 사람은 게임 목표와 MVP 범위, 팀 씬 협업 경계, 조작감 수치, 제외 기능, 실제 Play Mode 완료 여부를 직접 결정했다.

## 1. Codex를 어디에 사용했나요?

- 기존 입력·Player·GameFlow·씬 참조 구조 조사와 구현 계획 수립
- 3인칭 이동·카메라, 방향성 중력, 무중력, 그래플 등 Player·Gravity 기능 구현
- 지형 접지, 카메라 충돌, 중력 전환, 입력 타이밍과 무중력 관성 문제의 원인 분석·최소 수정
- 컴파일, Console, 씬 참조와 Play Mode 확인 항목을 기준으로 한 검증 및 작업 기록 정리

## 2. 어떤 기능을 구현했나요?

- Rigidbody 기반 3인칭 이동, 점프, 달리기·웅크리기, 조준·사격·리로드
- 카메라 충돌 방지, 거리 조절, 중앙·숄더 구도 프리셋
- Zone 기반 방향성 중력 전환과 Player·Camera 동기화
- 고정·주기·무중력 Preset, 무중력 사격 반작용, 그래플 이동
- 발소리·사격음·리로드음과 Zone 기반 동굴 환경음

## 3. 어떤 문제를 해결했나요?

- MeshCollider 지형에서 발생하던 접지 끊김·튐·걸림을 Grounded 속도 규칙과 제한적 Ground Snap으로 안정화했다.
- 중력 전환 때 Player와 Camera의 기준 Up이 어긋나는 문제를 공통 `PresentationUp` 전환으로 정리했다.
- 무중력 진입 시 관성이 사라지는 문제와 사격 반작용의 무한 가속 위험을 분리해 해결했다.
- 디버그 Preset 적용이 실제 Zone 진행 상태를 바꾸지 않도록 GameFlow와 테스트 기능의 책임을 분리했다.
- 그래플 외부 힘이 기존 Player 이동 속도 갱신에 의해 사라지는 문제를 PlayerController 내부 속도 오버레이로 해결했다.

## 4. 사람이 직접 결정한 부분은 무엇인가요?

- 초기 개발 목표와 Player·Gravity 파트의 마스터 플랜을 세우고, 구현이 MVP 목표와 팀 협업 범위를 벗어나지 않도록 우선순위와 제외 항목을 직접 관리했다.
- Codex가 제시한 구현 방향을 그대로 채택하지 않고, 플레이 경험·레벨 의도·기존 구조를 기준으로 의견과 아이디어를 주고받으며 더 적합한 방향으로 조율했다.
- 한 가지 기술적 해법에 편협하게 흐르지 않도록 대안을 비교하고, 필요한 경우 기능을 분리하거나 후속 작업으로 미뤘다.
- Play Mode에서 조작감, 중력 전환, 카메라 구도, 무중력 이동 등을 직접 피드백하여 수치와 세부 동작을 반복적으로 다듬었다.
- 팀장 소유 `Original_GamePlayScene`은 보호하고, Player·Gravity 통합은 `GamePlayScene_Player`에서만 진행했다.
- 컴파일 통과만으로 완료 처리하지 않고, 실제 조작 결과와 Console 상태를 최종 완료 기준으로 삼았다.
