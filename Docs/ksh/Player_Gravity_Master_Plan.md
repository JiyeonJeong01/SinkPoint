# 플레이어·중력 파트 마스터 계획

> 상태: 방향 공유와 합의 조정을 위한 수정 가능한 문서
>
> 최종 갱신: 2026-08-24
>
> 기준 기획: [SinkPoint MVP 게임 기획서](../GameDesign_MVP.md)

## 1. 목표

4일 안에 플레이어가 일반 중력, 방향이 바뀌는 중력, 무중력 구간을 통과하고 그래플로 다음 구간까지 진행할 수 있는 MVP를 만든다. 세부 구현은 한 번에 고정하지 않고 GitHub의 변경 단위에서 팀과 맞추되, 이 문서의 방향과 책임 경계는 유지한다.

우선순위는 다음과 같다.

1. 처음부터 끝까지 막히지 않는 플레이 흐름
2. 플레이어와 주변 Rigidbody가 함께 반응하는 중력 변화
3. 무중력에서의 단순하고 확실한 그래플 이동
4. 조작 안내와 최소 연출

## 2. 담당 범위

- 3인칭 플레이어 이동과 카메라
- 점프, Left Shift 전진 달리기, Left Ctrl 웅크리기
- 카메라 중심 조준과 무기 1개의 발사 애니메이션·Raycast 판정
- 현재 중력 방향을 기준으로 한 이동과 플레이어 정렬
- 구역에 따른 중력 방향·세기 변경
- 플레이어와 물리 오브젝트의 공통 중력 반응
- 무중력 상태와 그래플링 훅 이동

다음 항목은 이번 파트에서 확장하지 않는다.

- 실제 로프·진자 시뮬레이션
- 완성형 애니메이션과 고급 카메라 연출
- 범용 물리·능력 프레임워크
- 무기 다양화, 복잡한 전투와 적 AI
- 범용 아이템·인벤토리 시스템
- 팀장이 담당하는 지형 Collider의 중복 제작

## 3. 기술 방향

- 플레이어와 중력 반응 오브젝트는 Rigidbody 기반 사용자 정의 중력을 사용한다.
- 중력 방향과 세기는 하나의 공통 상태에서 관리하고, 플레이어와 잔해가 같은 기준으로 반응하게 한다.
- 중력의 영향을 직접 받는 Rigidbody는 Unity 기본 중력에 의존하지 않고 공통 중력 상태를 적용한다.
- 지형은 팀장이 Original 씬에 배치하는 BoxCollider와 충돌한다.
- 입력은 기존 [PlayerInput](../../Assets/_Scripts/Input/PlayerInput.cs)을 단일 입구로 사용한다.
- Left Shift는 전진 달리기, Left Ctrl은 웅크리기 입력으로 사용한다.
- 사격은 카메라 중심에서 조준점을 구한 뒤 총구에서 조준점까지 다시 검사해 가까운 장애물을 실제 적중으로 우선한다.
- 플레이어의 총구 Raycast는 살아 있는 `MonsterHealth`에 피해를 전달하고, 지네의 `Nav Target` Trigger는 `PlayerHealth`에 쿨타임 기반 접촉 피해를 전달한다. 체력 UI·사망 연출·리스폰 연결은 후속 시스템이 이벤트로 구독한다.
- 새 몬스터의 피격·접촉 판정 구성과 공동 테스트 절차는 [플레이어·몬스터 데미지 연동 가이드](../Player_Monster_Damage_Integration_Guide.md)를 따른다.
- 무중력 그래플은 카메라 중심 Raycast, 적중 지점 저장, 단순 끌어당김과 LineRenderer 표시까지만 구현한다.

구체적인 클래스 API, 수치와 상태 전이는 각 구현 변경에서 검증한 뒤 확정한다.

## 4. 단계별 방향

### 단계 1 — 기본 플레이어

- Rigidbody 이동, 카메라 회전, 지면 판정과 점프를 연결한다.
- 전진 달리기, 웅크리기, 카메라 상하 조준과 최소 사격 판정을 연결한다.
- 일반 중력 구간에서 BoxCollider 지형을 안정적으로 이동하는 상태를 완료 기준으로 삼는다.

### 단계 2 — 방향성 중력

- 공통 중력 상태가 실행 중 방향과 세기를 변경할 수 있게 하고, 구역 전환 이벤트를 실제 중력 변경에 연결한다.
- 먼저 일반 중력에서 한 방향의 90도 중력으로 전환하는 구간을 완성한다. 플레이어가 새 방향으로 떨어지고 정렬되며, 테스트 Rigidbody도 같은 방향으로 반응해야 한다.
- 한 방향 전환이 안정적으로 플레이된 뒤 역중력과 주기적 전환을 필요한 구역 순서대로 확장한다. 강한 중력과 약한 중력은 실제 진행에 필요할 때만 추가한다.
- 전환 후 새 바닥에서 이동과 점프가 가능하고, 지형 관통이나 조작 불능 상태가 발생하지 않는 것을 완료 기준으로 삼는다.

### 단계 3 — 무중력과 그래플

- 먼저 무중력 진입 시 남아 있는 낙하 속도와 일반 이동을 어떻게 처리할지 정하고, 무중력 진입과 일반 중력 복귀가 안전하게 이어지게 한다.
- 무중력에서 불필요한 낙하를 제거한 뒤 카메라 중심 Raycast, 적중 지점 저장, 단순 끌어당김과 선 표시를 연결해 목표 지점까지 이동시킨다.
- 적중 실패, 입력 종료, 도착 또는 시간 초과 시 그래플이 안전하게 끝나야 한다.
- 실제 로프 물리나 스윙을 추가하지 않고, 무중력 구간을 반복해서 통과할 수 있는 상태를 완료 기준으로 삼는다.

### 단계 4 — 팀 씬 통합과 WebGL 검증

- Collider가 반영된 최신 Original을 전달받은 뒤 `GamePlayScene_Player` 사본을 만든다.
- 플레이어 프리팹과 중력 구역을 통합하고 Entry부터 Source까지의 진행을 확인한다.
- 최종적으로 브라우저에서 별도 제어 없이 조작 가능한 WebGL 빌드를 검증한다.

일정은 팀의 씬·전투 진행 상황에 맞춰 조정할 수 있지만, 뒤 단계의 연출을 위해 앞 단계의 플레이 가능 상태를 희생하지 않는다.
플레이어 세부 조정과 아이템 구성은 Entry부터 Source까지의 핵심 경로를 먼저 연결한 뒤, 진행을 막는 문제나 팀에서 합의한 최소 기능에 한해 다룬다.

## 5. 협업 경계

- `Assets/_Scenes/Original_GamePlayScene.unity`는 팀장 소유 기준본으로 보고 우리 브랜치에서 직접 수정하지 않는다.
- Collider가 반영된 최신 씬을 받기 전에는 `GamePlayScene_Player`를 만들지 않는다.
- 공유가 필요한 상세 설계는 코드와 함께 GitHub 변경 단위로 설명한다.
- 다른 파트와 맞닿는 입력, 전투, 상호작용 인터페이스는 임의로 변경하지 않고 영향과 대안을 먼저 공유한다.
- 마스터 계획의 범위나 핵심 방향은 팀 합의 또는 담당자의 명시적 결정이 있을 때만 바꾼다.

## 6. MVP 완료 기준

- 일반 중력에서 이동, 카메라, 점프가 가능하다.
- 전진 달리기와 웅크리기가 Collider·애니메이션과 함께 동작하고, 카메라 조준 방향으로 사격 판정이 발생한다.
- 최소 한 구역에서 중력 방향이 바뀌며 플레이어와 Rigidbody 오브젝트가 함께 반응한다.
- 무중력 구간을 그래플로 통과할 수 있다.
- 중력 전환 후에도 지형을 뚫거나 조작 불능 상태에 빠지지 않는다.
- `GamePlayScene_Player`에서 Entry부터 Source까지 진행 가능한 통합 경로가 마련된다.
- WebGL 빌드에서 핵심 조작과 진행이 재현된다.
