## 1. 목표

MeshCollider 기반 지형의 언덕, 오목한 구간, 삼각형 경계와 작은 턱을 이동할 때 다음 문제를 플레이어 조작에 지장이 없는 수준까지 억제한다.

- 점프 입력 없이 플레이어가 위로 튀거나 Airborne으로 전환되는 현상
- 지면을 따라 이동할 때 순간적으로 걸리거나 속도가 끊기는 현상
- 언덕 정상과 오목한 지형에서 접지 판정이 짧게 끊기며 붕 뜨는 현상
- 작은 턱을 평지 장애물처럼 받아 이동이 멈추는 현상

모든 후보 조치를 구현하는 것이 목표가 아니다. 가장 작고 직접적인 조치부터 하나씩 적용하고, 매 조치 뒤 사용자 Play Mode 검증에서 만족할 만한 결과가 나오면 그 시점에 작업을 종료한다.

## 2. 실행 원칙과 중단 규칙

이 계획은 Phase 완료 방식으로 진행하지 않는다.

```text
현재 문제 재현
  -> 가장 작은 조치 1개 적용
  -> 컴파일·자동 확인
  -> 사용자 Play Mode 체감 확인
       ├─ 만족: 즉시 완료
       └─ 부족: 남은 증상을 분류하고 다음 조치 1개만 적용
```

- 뒤 순번은 앞 순번의 결과가 부족할 때만 실행한다.
- 한 번에 여러 이동 보정을 묶지 않는다. 어떤 조치가 개선 또는 회귀를 만들었는지 분리한다.
- 각 판정 게이트에서 사용자가 문제가 충분히 억제되었다고 확인하면 이후 순번은 미구현 상태로 남기고 전체 작업을 완료 처리한다.
- 수치 튜닝만으로 해결 가능한 상태라면 새 알고리즘을 추가하지 않는다.
- 특정 메시 조각의 결함만 남았다면 플레이어 컨트롤러에 예외 로직을 누적하지 않고 지형 소유자에게 충돌 메시 정리를 요청한다.

## 3. 범위

- `PlayerController`의 접지 판정과 Grounded 이동 속도 계약
- 명시적 점프와 물리 충돌로 발생한 비의도 상승의 구분
- 중력 방향을 기준으로 동작하는 접지 유지와 짧은 Ground Snap
- 필요한 경우 플레이어 CapsuleCollider의 마찰·반발 재질
- 필요한 경우 MeshCollider 삼각형 노멀 변화에 대한 지면 노멀 안정화
- 필요한 경우 허용 높이 이하의 작은 턱을 넘는 제한적 Step Assist
- Inspector에서 접지 상태와 보정 작동 여부를 확인할 수 있는 런타임 관찰값
- Normal 중력과 방향 전환 후 중력에서의 Play Mode 회귀 검증

## 4. 하지 않을 것

- `Assets/_Scenes/Original_GamePlayScene.unity` 수정
- 팀장 소유 지형 MeshCollider의 메시, 위치, 레이어 또는 Cooking 설정 변경
- 시각 지형과 별도의 충돌 지형을 임의로 제작
- Unity `CharacterController` 또는 별도 캐릭터 이동 프레임워크로 교체
- 플레이어 Rigidbody를 Kinematic 방식으로 전환
- 점프 높이, 점프 입력 버퍼 `0.1초`, 대쉬·웅크리기 또는 카메라 동작 변경
- 경사면 자동 슬라이딩, 등반 또는 파쿠르 기능 추가
- 무중력 이동, 무기 반작용 또는 중력 전환 연출 변경
- Collider 크기와 형태 변경
- `Packages`, `ProjectSettings`, Build Settings 또는 활성 빌드 타깃 변경
- WebGL 빌드

## 5. 현재 상태와 문제 근거

### 5.1 문서와 실제 지형의 차이

`Player_Gravity_Master_Plan.md`에는 아직 BoxCollider 지형을 기준으로 기록되어 있지만, 이 실행 계획은 사용자가 확정한 현재 MeshCollider 지형 운용을 전제로 한다. 이번 요청은 새 실행 계획서 작성이므로 마스터 계획 자체는 수정하지 않는다.

### 5.2 현재 플레이어 물리 구성

- 플레이어는 Dynamic Rigidbody와 CapsuleCollider를 사용한다.
- Rigidbody는 `useGravity = false`, Interpolate 활성, 연속 충돌 검사를 사용한다.
- CapsuleCollider에는 별도 Physics Material이 연결되어 있지 않다.
- 플레이어 회전은 방향성 중력에 맞춰 `PlayerController`가 소유하므로 Rigidbody 회전을 고정하지 않는다.
- 접지는 Capsule 중심에서 현재 중력 방향으로 `SphereCastNonAlloc`을 실행해 판정한다.
- `maxGroundAngle = 50`, `groundProbeDistance = 0.15`가 현재 기본값이다.

### 5.3 코드상 우선 확인할 원인

현재 `ApplyGroundedMotion()`은 입력 방향을 지면 노멀 평면에 투영하므로 정상적인 오르막 이동에는 필요한 위쪽 성분이 생긴다. 이 성분 자체를 제거하면 경사를 오를 수 없으므로 유지해야 한다.

반면 기존 Rigidbody 속도에서 중력축 성분을 가져올 때는 아래쪽 속도를 제거하고 위쪽 속도를 보존한다. 충돌 반발이나 메시 경계에서 생긴 위쪽 속도가 다음 물리 프레임까지 남을 수 있으므로, 명시적 점프가 아닌 비의도 상승의 첫 번째 수정 후보로 본다.

접지 판정은 가장 가까운 유효 SphereCast 한 건의 노멀을 사용한다. 언덕 정상, 오목한 접합부와 메시 삼각형 경계에서는 한 프레임의 접지 누락이나 노멀 급변이 발생할 수 있다.

## 6. 필요한 가정과 책임 경계

- 실제 점프는 기존 `PlayerInput -> jump buffer -> PlayerMotionStateMachine -> ApplyJump()` 경로만 사용한다.
- Grounded 이동 보정은 실제 점프 실행 프레임에 개입하지 않는다.
- 모든 방향 계산은 월드 Y축이 아니라 `GravityDirection`과 `Up`을 기준으로 한다.
- `PlayerController`가 Rigidbody 속도, 접지 쿼리, Snap과 Step Assist를 소유한다.
- `PlayerMotionStateMachine`은 Grounded, Airborne, ZeroGravity 상태 선택만 담당하며 지형 쿼리를 중복 소유하지 않는다.
- 지형 MeshCollider는 이번 작업에서 읽기 전용이다.
- 최종 조작감의 정본은 사용자의 실제 Play Mode 확인이다. 컴파일과 자동 이동은 체감 완료 근거로 대신하지 않는다.

## 7. 기준 재현과 관찰 항목

동작을 바꾸기 전에 `GamePlayScene_Player`에서 대표 문제 지점을 최소 세 종류로 정한다.

1. 완만한 언덕 또는 언덕 정상
2. 움푹 들어가거나 삼각형이 만나는 지형
3. 이동이 걸리는 작은 턱

각 지점에서 걷기와 달리기를 각각 같은 방향으로 반복하고 다음을 구분한다.

- 입력 없이 점프 동작이 실행됐는지
- `Grounded -> Airborne` 전환만 발생했는지
- Rigidbody에 중력 기준 위쪽 속도가 생겼는지
- 접지는 유지되지만 마찰 또는 충돌로 전진 속도만 끊겼는지
- 특정 위치·진입 방향에서만 반복되는지

기존 Inspector만으로 구분하기 어렵다면 `PlayerController`에 다음 읽기 전용 런타임 표시를 먼저 추가한다.

- 현재 Motion State와 Grounded 판정
- 현재 지면 각도와 지면까지의 거리
- 중력 기준 수직 속도
- 마지막 실제 점프 실행 여부
- Ground Snap 또는 Step Assist 작동 여부

관찰값은 진단용이며 게임 로직의 정본으로 사용하지 않는다.

## 8. 순차 실행 계획

### 순번 1 — Grounded 속도 계약에서 비의도 상승 제거

가장 먼저 `ApplyGroundedMotion()`에서 이전 프레임의 중력축 속도를 보존하는 방식을 수정한다.

- 지면 노멀 평면에 투영한 입력 이동은 유지해 경사 오르내리기를 보존한다.
- Grounded 상태에서는 이전 충돌에서 남은 중력축 속도를 새 이동 속도에 다시 합치지 않는다.
- 지면을 향한 접촉 유지 힘은 유지하되, 실제 점프는 기존 `ApplyJump()`만 위쪽 이탈 속도를 만들게 한다.
- Airborne의 낙하 속도와 ZeroGravity 관성은 변경하지 않는다.

1. `[기준 지점과 런타임 값 기록]` → verify: `[언덕·오목 지형·턱의 증상을 상승, 접지 누락, 전진 걸림으로 구분]`
2. `[Grounded의 이전 중력축 속도 보존 제거]` → verify: `[입력 이동의 지면 접선 성분과 실제 점프 속도는 유지]`
3. `[컴파일과 좁은 상태 회귀 확인]` → verify: `[Grounded·Airborne·ZeroGravity 상태 전환과 점프 입력 버퍼 오류 없음]`
4. `[사용자 Play Mode 판정]` → verify: `[대표 세 지점의 비의도 도약과 걸림이 허용 가능한 수준인지 확인]`

판정 게이트:

- 만족하면 여기서 종료한다.
- 점프처럼 튀는 현상은 사라졌지만 접촉 마찰로 걸리면 순번 2로 이동한다.
- 언덕 정상이나 굴곡에서 접지가 끊기며 붕 뜨면 순번 3으로 이동한다.

#### 순번 1 구현·자동 검증 기록 — 2026-08-25

- `ApplyGroundedMotion()`이 이전 Rigidbody 속도의 중력축 성분을 새 Grounded 속도에 다시 합치지 않도록 수정했다.
- 입력 이동은 기존처럼 현재 지면 노멀 평면에 투영하므로 오르막과 내리막의 접선 이동 성분은 유지한다.
- 실제 점프는 기존 `PlayerMotionStateMachine -> ApplyJump()` 경로만 사용하며 점프 입력 버퍼와 Airborne 이동은 변경하지 않았다.
- Inspector Runtime State에 현재 Grounded Probe 결과, 지면 각도, 이동 적용 전 중력 Up 기준 속도와 이번 물리 프레임의 실제 점프 실행 여부를 추가했다.
- Unity 6000.3.20f1에서 스크립트 재컴파일이 `failed: false`, 오류 0건으로 완료됐다.
- 새 Play Mode에서 `/GamePlay/Player`의 `runtimeGrounded = true`, `runtimeGroundAngle = 9.21`, `runtimeVerticalSpeedBeforeMotion = 0.0013`, `runtimeJumpExecuted = false`를 확인했다.
- 깨끗한 Console 기준으로 Play Mode 진입·종료 사이 신규 Error는 0건이었다.
- 자동 검사는 문제 지형을 실제 입력으로 횡단하거나 점프 조작감을 검증하지 못한다. 대표 언덕·오목 지형·턱의 사용자 Play Mode 확인 전에는 순번 1을 완료 판정하거나 순번 2로 진행하지 않는다.
- 순번 2 이후의 Physics Material, Ground Snap, 노멀 안정화와 Step Assist는 구현하지 않았다.

2026-08-25 사용자 Play Mode 확인:

- 지형 이동 문제가 약 90% 억제됐고, 경사로와 턱에서 발생하던 비의도 상승과 걸림은 거의 사라졌다.
- 울퉁불퉁한 지형에서 순간적으로 낙하 판정이 발생하며 덜덜거리면서 떨어지는 접지 단절만 남았다.
- 순번 1은 유효한 개선으로 유지한다.
- 접촉 마찰성 걸림이 주 증상으로 남지 않았으므로 순번 2는 미실행 상태로 건너뛴다.
- 남은 증상이 `Grounded -> Airborne` 순간 전환에 해당하므로 사용자 승인에 따라 순번 3으로 진행한다.

### 순번 2 — 플레이어 접촉 마찰과 반발 최소화

실행 상태: **미실행 — 순번 1에서 마찰성 걸림이 거의 해소돼 순번 3으로 직접 진행**

접지는 유지되지만 MeshCollider 경계나 턱에서 전진이 걸리는 현상이 남을 때만 실행한다.

- 플레이어 전용 Physics Material을 추가한다.
- Bounciness는 `0`, Bounce Combine은 반발이 생기지 않는 방식으로 둔다.
- Static/Dynamic Friction은 `0`부터 검사하고, Friction Combine도 지형 재질의 마찰을 되살리지 않는 방식으로 둔다.
- 지형 MeshCollider 재질은 변경하지 않고 Player CapsuleCollider에만 연결한다.
- 경사 정지와 이동은 커스텀 속도·중력이 계속 담당한다.

1. `[플레이어 전용 무반발·저마찰 재질 추가와 Capsule 연결]` → verify: `[지형 Collider와 다른 Prefab에는 변경 없음]`
2. `[평지·언덕·턱 걷기와 달리기 비교]` → verify: `[걸림 감소, 과도한 미끄러짐과 정지 불능 없음]`
3. `[사용자 Play Mode 판정]` → verify: `[접촉감과 제동감이 만족스러운지 확인]`

판정 게이트:

- 만족하면 여기서 종료한다.
- 언덕 정상과 오목한 곳의 순간 Airborne만 남으면 순번 3으로 이동한다.
- 마찰 변경이 조작감을 악화시키면 재질 연결을 최종안으로 채택하지 않고 순번 1 상태에서 다음 원인을 판단한다.

### 순번 3 — 짧은 Ground Snap으로 접지 연속성 보완

경사와 굴곡에서 바닥이 짧게 멀어져 접지 판정이 끊길 때만 실행한다.

- 접지 쿼리가 지면 노멀뿐 아니라 지면 거리도 반환하게 한다.
- 직전 물리 프레임에 Grounded였고 짧은 거리 안에 유효 지면이 있을 때만 Snap 후보가 된다.
- 실제 점프가 실행됐거나 중력 기준 위쪽 이탈 속도가 임계값보다 크면 Snap하지 않는다.
- 중력 전환 중과 ZeroGravity에서는 Snap하지 않는다.
- 순간 위치 텔레포트보다 제한된 지면 방향 속도로 간격을 닫는 방식을 우선한다.
- `snapDistance`, `maxSnapSpeed`와 작동 여부를 Inspector에서 확인할 수 있게 한다.

1. `[접지 결과에 거리와 직전 접지 상태 추가]` → verify: `[Normal과 방향 전환 중력에서 같은 기준으로 계산]`
2. `[점프 제외 조건이 있는 짧은 Snap 적용]` → verify: `[언덕 정상·오목 지형의 순간 Airborne 감소]`
3. `[의도된 이탈 회귀 검사]` → verify: `[점프 높이, 낭떠러지 추락, 중력 전환 후 낙하를 붙잡지 않음]`
4. `[사용자 Play Mode 판정]` → verify: `[지면 추종이 자연스럽고 자석처럼 달라붙지 않는지 확인]`

판정 게이트:

- 만족하면 여기서 종료한다.
- 접지는 유지되지만 삼각형마다 이동 방향이 흔들리면 순번 4로 이동한다.
- 작은 수직 턱에서만 진행이 막히면 순번 5로 이동한다.

#### 순번 3 구현·자동 검증 기록 — 2026-08-25

- 접지 쿼리를 `TryGetGroundSupport()`로 확장해 유효 지면 노멀과 캡슐 하단 기준 지면 거리를 함께 반환하게 했다.
- 기존 `groundProbeDistance = 0.15` 안에서 지면을 찾지 못했을 때만 `groundSnapDistance = 0.3`까지 두 번째 지지면 검사를 실행한다.
- 직전 모션 상태가 `Grounded`이고 중력이 활성화됐으며, 보정 전 위쪽 속도가 `maxGroundSnapUpwardSpeed = 0.5` 이하일 때만 Snap 후보가 된다.
- Snap 속도는 현재 중력 방향을 사용하고 `maxGroundSnapSpeed = 5`로 제한한다. 이미 같은 방향 속도가 충분하면 추가 속도를 더하지 않는다.
- 실제 점프가 실행된 프레임에는 Snap 속도를 적용하지 않는다. 중력 전환 중에는 접지 처리를 조기 종료하고, ZeroGravity에서는 Snap 후보가 되지 않는다.
- Inspector Runtime State에 `runtimeGroundDistance`와 `runtimeGroundSnapActive`를 추가했다.
- Unity 6000.3.20f1에서 스크립트 재컴파일이 `failed: false`, 오류 0건으로 완료됐다.
- 새 Play Mode 기본 위치에서 설정값 `0.3 / 5 / 0.5`, `runtimeGrounded = true`, `runtimeGroundDistance = 0`, `runtimeGroundSnapActive = false`가 정상적으로 표시·갱신됐다.
- 깨끗한 Console 기준으로 Play Mode 진입·종료 사이 신규 Error는 0건이었다.
- `Original_GamePlayScene`, 지형 Collider, Packages, ProjectSettings와 Build Settings는 변경하지 않았다.
- 자동 검사는 문제의 울퉁불퉁한 지형 횡단, 실제 점프 높이와 낭떠러지 이탈 조작감을 증명하지 않는다. 사용자 Play Mode 확인 전에는 완료 처리하거나 순번 4로 진행하지 않는다.
- 순번 4 이후의 노멀 안정화와 Step Assist는 구현하지 않았다.

2026-08-25 사용자 Play Mode 최종 확인:

- 사용자가 순번 3 적용 후 지형 이동 결과를 직접 확인하고 현재 상태가 만족할 만하다고 판정했다.
- 순번 1의 Grounded 속도 계약 수정과 순번 3의 짧은 Ground Snap을 최종 구현으로 유지한다.
- 추가 노멀 보정이나 Step Assist 없이 목표를 달성했으므로 남은 순번은 실행하지 않고 작업을 완료한다.

### 순번 4 — MeshCollider 지면 노멀 안정화

실행 상태: **미실행 — 순번 3에서 사용자 만족 기준을 충족해 종료**

지면 삼각형 경계에서 노멀이 급변해 이동 방향이 흔들릴 때만 실행한다.

- 경사 허용 여부를 판단하는 원본 hit normal과 이동에 사용하는 support normal의 책임을 분리한다.
- Grounded가 연속되는 동안에만 이전 유효 support normal과 현재 normal 사이의 급격한 변화를 제한한다.
- 허용 경사 초과 면을 안정화라는 이유로 지면으로 받아들이지 않는다.
- 단순 보간으로 해결되지 않으면 캡슐 하단 범위의 제한된 추가 샘플로 지지면을 판단하되, 무제한 Raycast나 매 프레임 할당을 추가하지 않는다.
- 절벽 가장자리와 서로 반대인 면의 노멀을 평균해 허공 방향을 만드는 경우를 차단한다.

1. `[지면 판정 normal과 이동 support normal 분리]` → verify: `[maxGroundAngle 계약 유지]`
2. `[연속 Grounded 구간의 normal 변화 제한]` → verify: `[삼각형 경계 이동 방향 진동 감소]`
3. `[절벽·급경사 경계 검사]` → verify: `[걸을 수 없는 벽을 지면으로 오인하지 않음]`
4. `[사용자 Play Mode 판정]` → verify: `[언덕과 오목 지형에서 방향 변화가 자연스러운지 확인]`

판정 게이트:

- 만족하면 여기서 종료한다.
- 허용해야 할 작은 턱에서만 전진이 막히면 순번 5로 이동한다.
- 특정 메시 조각에서만 문제가 남으면 순번 6의 지형 진단으로 이동한다.

### 순번 5 — 제한적 Step Assist

실행 상태: **미실행 — 순번 3에서 사용자 만족 기준을 충족해 종료**

허용 높이 이하의 작은 턱을 부드럽게 넘어야 한다는 사용자 판정이 있을 때만 실행한다.

- `maxStepHeight`와 `stepProbeDistance`를 명시적인 Inspector 설정으로 둔다.
- Grounded이고 이동 입력이 있을 때만 검사한다.
- 진행 방향의 낮은 위치가 막히고, 높은 위치의 캡슐 공간은 비어 있으며, 턱 위에 유효한 지지면이 있을 때만 Step으로 인정한다.
- 위쪽 속도를 가해 튀어 오르는 방식은 사용하지 않는다.
- 한 FixedUpdate에 허용되는 위치 보정량을 제한하고 Rigidbody 이동 경로를 사용한다.
- 경사 한계를 넘는 면, 공중, 점프 중, 중력 전환 중과 ZeroGravity에서는 작동하지 않는다.
- 중력 방향이 바뀌어도 현재 `Up` 기준으로 턱 높이를 계산한다.

1. `[낮은 장애물·상단 여유·위쪽 지지면 검사 추가]` → verify: `[허용 턱만 Step 후보가 됨]`
2. `[제한된 Rigidbody 위치 보정 적용]` → verify: `[수직 발사와 벽 타기 없이 턱 통과]`
3. `[캡슐 여유와 경사 실패 경로 검사]` → verify: `[낮은 천장, 높은 벽, 낭떠러지에서 작동하지 않음]`
4. `[사용자 Play Mode 판정]` → verify: `[대표 턱 통과가 자연스럽고 카메라 흔들림이 허용 가능한지 확인]`

판정 게이트:

- 만족하면 완료한다.
- 복잡한 예외를 더 추가해야 할 정도로 특정 위치만 실패하면 순번 6으로 이동한다.

### 순번 6 — 지형 충돌 메시 개선 요청으로 전환

실행 상태: **미실행 — 순번 3에서 사용자 만족 기준을 충족해 종료**

앞선 보정 뒤에도 특정 삼각형, 과도하게 얇은 턱 또는 비정상 접합부에서만 문제가 반복되면 컨트롤러 수정을 중단한다.

- 문제 위치, 진입 방향, Grounded 상태, hit normal과 지면 각도를 기록한다.
- 중복 면, 뒤집힌 노멀, 지나치게 작은 삼각형, 열린 경계와 급격한 요철 여부를 읽기 전용으로 확인한다.
- 지형 소유자에게 단순화된 충돌 메시, 접합부 정리 또는 필요한 Cooking 설정 검토를 요청한다.
- 사용자의 별도 승인과 최신 Original 씬 인계 없이 지형 Collider를 직접 수정하지 않는다.

이 경우 플레이어 컨트롤러의 무제한 예외 처리가 아니라 지형 데이터 개선 요청까지를 이번 작업의 적절한 종료점으로 본다.

## 10. 공통 검증 기준

### 매 순번 자동·정적 확인

- 런타임·Editor 어셈블리 컴파일 오류 0건
- 신규 Console Error 0건
- Grounded, Airborne, ZeroGravity 상태 고착 없음
- NaN·Infinity 속도와 비정상적인 Rigidbody 회전 없음
- `Original_GamePlayScene`, 지형 Collider, Packages, ProjectSettings와 Build Settings diff 없음
- 사용자 기존 작업 트리 변경 보존

### 매 순번 Play Mode 확인

- 평지 정지, 걷기, 달리기가 기존처럼 동작한다.
- 완만한 언덕을 오르내릴 때 입력 없는 도약과 반복 Airborne이 없다.
- 오목한 지형과 메시 경계에서 이동 속도가 과도하게 끊기지 않는다.
- 실제 Space 점프의 높이, 방향, 입력 버퍼와 착지가 유지된다.
- 낭떠러지를 벗어나면 정상적으로 Airborne과 낙하로 전환된다.
- 최대 허용 경사보다 가파른 면을 걸어 올라가지 않는다.
- 웅크리기, 전진 달리기, 카메라와 사격이 회귀하지 않는다.
- 최소 Normal 중력과 실제 사용하는 방향 전환 중력 하나에서 같은 동작을 확인한다.
- 중력 전환 도중 위치 고정과 전환 완료 후 낙하를 접지 보정이 방해하지 않는다.

### 최종 사용자 만족 기준

다음 조건을 사용자가 실제 조작으로 확인하면 남은 순번을 실행하지 않고 완료한다.

- 대표 언덕·오목 지형·턱에서 점프 입력 없는 도약이 재현되지 않거나 게임 진행에 지장이 없는 수준이다.
- 이동 중 걸림과 속도 끊김이 의도한 지형 형태로 받아들일 수 있는 수준이다.
- 실제 점프, 경사 이동과 낭떠러지 이탈이 부자연스럽게 억제되지 않는다.
- Normal과 방향 전환 중력 모두에서 조작감이 만족스럽다.
