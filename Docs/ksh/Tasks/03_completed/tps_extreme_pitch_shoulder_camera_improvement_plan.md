# TPS 카메라 구도 프리셋·숄더 뷰 빠른 검증 실행 계획

문서 작성일: 2026-08-25  
현재 상태: 완료 (2026-08-25)  
계획 프로필: `standard`

## 목표

현재 `-85° ~ 85°` 피치 범위와 기존 카메라 조작을 유지하면서, 카메라 구도를 간단한 프리셋으로 분리한다.

기존 중앙 구도를 비교 기준으로 보존하고, 게임 전반에 사용할 중간 거리 숄더 뷰를 빠르게 구현해 일반 이동·사격·중력 전환·그래플 구간에 어울리는지 사용자 Play Mode 테스트로 판단한다.

## 이번 기본 실행 범위

- `Centered`와 `ShoulderGameplay` 두 카메라 구도 프리셋
- Inspector에서 선택할 수 있는 현재 구도 프리셋
- `ShoulderGameplay`를 기본 선택값으로 적용
- 숄더 오프셋을 반영한 카메라 최종 위치와 지형 충돌 경로
- `ThirdPersonCameraRig.prefab`의 초기 숄더 구도값
- 화면 중앙 카메라 Ray 기반 사격·그래플 회귀 확인
- 일반 중력과 방향 전환 중력에서의 숄더 방향 확인
- 사용 가능한 게임 진행 구간 전반의 사용자 Play Mode 테스트

## 조건부 후속 범위

다음 항목은 이번 기본 구현에 포함하지 않는다. 기본 숄더 뷰 테스트 후 사용자가 필요하다고 판단한 경우에만 별도 순번으로 진행한다.

- 위쪽 극단 피치에 따른 동적 숄더 오프셋
- 카메라 근접도에 따른 플레이어 디더 페이드
- 좌우 어깨 전환
- 상황별 자동 프리셋 전환

## 하지 않을 것

- 현재 `minPitch = -85`, `maxPitch = 85` 제한 축소
- `Assets/_Scenes/Original_GamePlayScene.unity` 수정
- Player 또는 지형 Collider 변경
- Cinemachine 도입이나 카메라 시스템 전면 교체
- 1인칭 전환, 머리·팔 전용 렌더링 또는 무기 카메라 추가
- 자동 락온이나 조준 FOV 상태 추가
- 사격·그래플 판정 또는 탄착점 계약 변경
- 캐릭터 머티리얼·셰이더 변경
- `Packages`, `ProjectSettings`, Build Settings 또는 활성 빌드 타깃 변경
- 명시적 승인 없는 WebGL 빌드

## 현재 상태와 필요한 가정

- Camera Rig는 Player 위치를 따라가고, `CameraPivot` 높이 `1.03`, Pivot pitch와 Main Camera의 로컬 Z 거리로 현재 중앙 구도를 만든다.
- Main Camera가 현재 `x = 0`인 캐릭터 중심축에 있어 거의 수직으로 위를 보면 시선이 플레이어 몸통을 통과한다.
- 지형 충돌은 Pivot에서 카메라 뒤쪽으로 `SphereCastNonAlloc`을 실행하고 Player 계층 Collider를 제외한다.
- `PlayerCombatController`는 화면 중앙 카메라 Ray로 조준점을 구한 뒤 총구에서 그 지점으로 사격한다.
- 그래플도 카메라 중심 Raycast를 정본으로 사용한다.
- 방향성 중력 전환은 `ThirdPersonCameraController`가 재구성한 Rig의 로컬 축을 사용한다. 숄더 방향은 월드 X가 아니라 해당 Rig의 로컬 right를 기준으로 해야 한다.
- 초기 수치는 빠른 비교를 위한 후보이며 최종 구도는 사용자의 실제 Play Mode 확인으로 결정한다.

## 프리셋 계약

`ThirdPersonCameraController`가 구도 프리셋 선택과 적용을 소유한다. 별도 ScriptableObject나 범용 카메라 상태 머신은 만들지 않고, 현재 컴포넌트 안의 직렬화 가능한 간단한 설정으로 시작한다.

각 프리셋은 구도에 직접 필요한 값만 가진다.

- Pivot 높이
- 카메라 로컬 측면·수직 오프셋
- 기본 거리
- Camera FOV

사용자 줌 최소·최대 거리, 충돌 반경·여유, Tween과 입력 설정은 프리셋에 중복하지 않고 기존 카메라 공통 설정으로 유지한다.

### `Centered`

- 현재 구도를 그대로 재현하는 회귀 비교용 프리셋
- 측면·수직 오프셋 `0`
- 현재 Pivot 높이 `1.03`, 기본 거리 `1.605`, FOV `60`에서 시작

### `ShoulderGameplay`

- 게임 전반 테스트용 기본 프리셋
- 오른쪽 측면 오프셋 `0.35m`를 초기 후보로 사용
- Pivot 높이, 기본 거리 `1.605`, FOV `60`은 우선 `Centered`와 동일하게 유지
- 실제 플레이에서 캐릭터 크기나 주변 시야가 부적절할 때 프리셋 수치만 좁게 조정

Inspector의 프리셋 선택은 명확히 노출하고 Play Mode에서도 현재 선택값을 바꿔 두 구도를 빠르게 비교할 수 있게 한다. 프리셋 전환 입력이나 자동 전환 규칙은 추가하지 않는다.

## 책임 경계와 변경 방향

### 카메라 위치와 충돌

카메라 희망 위치는 선택된 프리셋의 로컬 오프셋과 현재 사용자 거리를 조합해 계산한다. 충돌 검사는 기존 중심축 뒤쪽만 Cast하지 않고 Pivot에서 이 최종 희망 위치까지의 벡터를 사용한다.

장애물 접근 시 안전 위치를 즉시 적용하고, 장애물 이탈 시 기존 거리 복귀 보간을 유지한다. Player 계층 Collider와 Trigger 제외 계약도 유지한다.

### 조준과 그래플

화면 중앙 Camera Ray를 조준·그래플 정본으로 유지한다. 숄더 오프셋으로 화면 구도는 달라져도 `카메라 조준점 → 총구 수렴`과 카메라 중심 그래플 Raycast 흐름은 변경하지 않는다.

### 방향성 중력

숄더 오프셋은 Camera Rig의 로컬 right/up을 사용한다. 중력 방향 변경 중에는 기존 Player·Camera 동기 회전을 보존하고, 숄더 오프셋 때문에 추가 Roll이나 별도 전환 상태를 만들지 않는다.

## 빠른 실행 계획

1. `[현재 중앙 구도값을 Centered 프리셋으로 보존]` → verify: `[Centered 선택 시 변경 전 Pivot 높이·거리·FOV·중심축 구도가 동일]`
2. `[ShoulderGameplay 프리셋과 Inspector 선택 추가]` → verify: `[Play Mode에서 두 프리셋을 바꿔 즉시 비교할 수 있고 ShoulderGameplay가 기본 선택됨]`
3. `[선택된 프리셋의 로컬 오프셋을 카메라 위치에 적용]` → verify: `[일반·방향 전환 중력 모두 같은 캐릭터 기준 오른쪽 어깨 구도를 유지]`
4. `[숄더 희망 위치까지 카메라 충돌 경로 수정]` → verify: `[벽·모서리에서 지형 관통이 없고 Player Collider는 계속 제외됨]`
5. `[컴파일·Prefab 참조와 좁은 자동 회귀 확인]` → verify: `[오류, Missing Script, Missing Reference 0건과 기존 씬 override 보존]`
6. `[사용자 Play Mode 전체 구도 테스트]` → verify: `[일반 이동·사격·극단 피치·좁은 통로·중력 전환·가능한 그래플 진행에서 숄더 뷰 적합성 확인]`
7. `[숄더 프리셋 수치 1차 확정]` → verify: `[사용자 확인을 반영해 프리셋 값만 조정하고 추가 카메라 기능 없이 만족 여부 재확인]`

## Play Mode 판정 항목

- 일반 이동과 탐사에서 캐릭터가 너무 크거나 한쪽 시야를 과도하게 가리지 않는다.
- 화면 중앙 조준점과 실제 총구 탄착점의 기존 수렴 계약이 유지된다.
- 그래플 표적 선택이 숄더 오프셋 전과 같은 화면 중앙 기준으로 동작한다.
- 위쪽 극단 피치에서 중앙 구도보다 플레이어 내부 메시 노출이 줄어든다.
- 오른쪽 벽, 왼쪽 벽, 모서리와 좁은 통로에서 카메라 관통이나 심한 떨림이 없다.
- 90도 중력 전환 중 카메라가 과도한 측면 원호를 그리거나 전환 후 어깨 방향이 뒤집히지 않는다.
- 중력 전환 직후 이동·사격·그래플 방향이 화면 기준과 일치한다.
- 줌과 장애물 이탈 거리 복귀가 기존처럼 동작한다.

## 조건부 후속 판단

기본 숄더 뷰를 프리셋 수치로 조정한 뒤에도 문제가 남을 때만 다음 조치를 검토한다.

1. 극단 위쪽 피치에서만 몸통 가림이 남음 → 피치 연동 동적 숄더 오프셋 계획
2. 벽 충돌이나 최소 줌에서 카메라가 메시 내부로 들어감 → 플레이어 근접 디더 페이드의 셰이더 호환성 조사
3. 한쪽 벽에서 지속적으로 시야가 불리함 → 좌우 어깨 전환 필요성 판단
4. 탐사와 전투에 필요한 구도가 명확히 다름 → 상황별 프리셋 전환을 별도 설계

이 조건부 항목은 사용자의 별도 진행 결정 없이 구현하지 않는다.

## 완료 기준

- `Centered`와 `ShoulderGameplay`가 Inspector에서 명확히 선택되고 Play Mode 비교가 가능하다.
- 기본 프리셋은 `ShoulderGameplay`이며 `-85° ~ 85°` 피치 범위가 유지된다.
- 숄더 위치를 반영한 지형 충돌과 기존 거리·줌 동작이 정상이다.
- 사격·그래플의 화면 중앙 Ray 계약이 유지된다.
- Normal 중력과 방향 전환 중력에서 숄더 방향과 조작 기준이 일관된다.
- 컴파일 오류, Missing Script, Missing Reference와 신규 Console 오류가 없다.
- `Original_GamePlayScene`, Collider, Packages, ProjectSettings와 Build Settings에 의도하지 않은 변경이 없다.
- 최종 완료 여부와 프리셋 수치는 사용자의 실제 Play Mode 확인으로 확정한다.

## 확정 결과

- `Centered`와 `ShoulderGameplay` Inspector 프리셋을 구현했고, 기본 선택은 `ShoulderGameplay`다.
- 두 프리셋의 Pivot 높이 `1.03`, 기본 거리 `1.605`, FOV `60`을 유지했으며 `ShoulderGameplay`의 오른쪽 측면 오프셋은 `0.35m`로 확정했다.
- 공통 사용자 줌 거리는 `0.6 ~ 2.5`로 확정하고 `ThirdPersonCameraRig.prefab`에 저장했다.
- 최종 카메라 희망 위치까지의 충돌 경로와 화면 중앙 Ray 기반 사격 계약을 유지했다.
- 좌우 어깨 전환, 자동 프리셋 전환, 피치 연동 오프셋, 플레이어 디더 페이드는 미실행 후속 항목으로 남긴다.

- 사용자가 실제 Play Mode에서 최대 거리 `2.5`를 조정하고 작업 성공을 확인했다.
